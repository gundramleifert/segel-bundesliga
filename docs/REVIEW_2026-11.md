# Concept review 2026-11 — the backlog

A critical review of the repository on 2026-11-11, one reviewer per concept. Every finding
was checked in the code at the time (`main` @ `cd6243a`…`bf17731`); line numbers drift, so
re-check before acting. Findings marked *(unverified)* were reasoned from the code, not run.

**How to use this file:** work top to bottom within a section, tick the box, and put the
commit hash behind it. A finding that turns out wrong is struck through with the reason —
not deleted. When a section is done, the rule it taught goes into `CLAUDE.md` (one line)
and this file shrinks. Delete the file when every box is ticked.

Severity: **H** high · **M** medium · **L** low.

## The five patterns behind most findings

1. **Rules that live only in prose.** "Only X writes Y" in `CLAUDE.md`, nothing in the code
   stopping a second writer. Agents break exactly these. → Every invariant belongs in a type,
   a DB constraint, a route dependency or a lint rule.
2. **The same truth in several places** — stored and computed standings, Person and User,
   membership row and tuple, the SAP name twice, "racing has started" five ways, workspace
   sections in 5–7 places, `CLAUDE.md` vs `MODEL`.
3. **"Derived, never stored" applied where it is wrong.** Right for points; wrong for money
   once decided and for a season's rules once sailed. Missing rule: *what is decided or paid
   is frozen*.
4. **Authorization inherits too widely**, so escape hatches (raw tuple reads) grew around it.
5. **Built ahead of need, verified behind it** — partial payments, tracking, OpenFGA
   compatibility, process ceremony; but no CI, SQLite-only tests, `main` red.

## 1. Money (expenses, payments, SEPA)

- [ ] **1.1 H — A claim can be paid twice.** The GiroCode (`services/payments.py:268-293`)
  records no payment; the claim stays open until "Mark as paid" (`routers/expenses.py:601-615`),
  and the next run takes every open claim (`payments.py:129-145`). "Mark as paid"
  (`expenses.py:657-674`) and `create_run` (`payments.py:145,193`) both read `open_cents`
  then insert, with no row lock (no `with_for_update` in `app/`) and no unique constraint.
  Fix: one active payment per claim enforced in the DB; fetching a GiroCode issues a payment.
- [ ] **1.2 H — Two "who pays" rules, partly outside the model.** Deciding and "Mark as paid"
  use `may_decide` (`expenses.py:126-137`: `check(treasurer)` plus a raw `authz.read(manager)`);
  runs, booking and returns use `may_pay_for` (club treasurer only, `:113-117`). So a series
  admin or event manager can mark paid what the treasurer never paid. `_decider_scope`
  (`:315-330`) re-implements the model in SQL. Docs disagree (`finance.py:291`, Story F-4,
  `CLAUDE.md`). Fix: only the paying club's treasurer decides and pays; one relation, `check()` only.
- [ ] **1.3 M-H — A wrong "Mark as paid" cannot be undone.** `POST /payments/{id}/fail`
  is 404 when `run_id is None` (`routers/payments.py:247`); `DRAFT`/`CANCELLED` are never
  written. Fix: one audited "reverse" transition for any payment.
- [ ] **1.4 M-H — Booked amounts are derived, not frozen.** `approved_cents` is a live sum
  (`finance.py:180-183`), `Payment.amount_cents` too (`:380`), the SEPA file is rebuilt on
  every download (`payments.py:227-255`). Fix: store amounts at approval/issue, store the
  exported XML (or its hash) on the run. Add the "decided money is frozen" rule to `CLAUDE.md`.
- [ ] **1.5 M — Claim transitions are scattered.** The router renames, removes items, attaches
  receipts with its own checks (`routers/expenses.py:302-313, 318-338, 394-470`);
  `personal.forget` moves drafts to `WITHDRAWN` without audit and clears
  `decided_by_user_id` (`services/personal.py:128-146`); booking a run audits only the run
  (`payments.py:299-307`). Fix: one `transition(claim, to, actor)` with a table of allowed
  moves that always audits.
- [ ] **1.6 M — Partial-payment machinery nobody uses (YAGNI).** Only full allocations are
  ever written; the allocation table, `PARTIALLY_PAID`, payment `DRAFT`/`CANCELLED` exist for

  drop it, or mark F-4 ◐.

  (`can_setup`, `can_decide_claims`, `can_view_documents`); drop the two inheritances.
- [ ] **4.2 H — No single answer to "what may I do here".** Frontend gates three ways:

  mismatches: issue #37, plus **Trackers** shown for `manager` but backend needs
  race_officer (`tracking.py:34`). Fix: one `GET /api/access/{object}` returning `can_*`;
  every section declared against it; retire `hasRole` for gating.
- [ ] **4.3 M-H — The generic tuple API skips workflows.** `write_tuple`
  (`routers/auth.py:580`) lets an object admin write any relation for any account found by

  IBANs. Fix: "workflow-owned relations" in the model (jury, guardian, judge); enforce the
  membership rule for club tuples in `grants.grant`.
- [ ] **4.4 M — The interpreter has two traps; the OpenFGA claim is in name only.** MODEL is

  the rules in SQL (misses a host club's treasurer/helper). Fix: `check` takes only loaded
  objects (raise otherwise); one SQL `reach(user, relation, type)` for every list; drop the
  swap-to-OpenFGA promise.
- [ ] **4.5 M — Gates opt-in per call site; writes bypass `grants.py`.** 102 of 217 routes

- [ ] **4.6 M — Draw is `require_admin`** (`admin.py:116`) while `CLAUDE.md` says event

- [ ] **4.7 M-L — The interpreter is barely tested.** `tests/unit/test_authz.py`: 75 lines,
